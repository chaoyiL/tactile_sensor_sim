# 触觉传感器光学仿真使用说明

## 曲面仿真入口

新增 `simulate_curve.py`，从 `configs/analytic.json` 读取弯曲参数。例如运行 `python simulate_curve.py --radius-mm 100 --reference --out results_curve_render/analytic/new_run`。平面与曲面统一使用 `center_uv` 指定压入位置；曲面压入深度沿局部法向。`--reference` 保持当前曲率，`--flat` 才取消弯曲。详见[曲面使用说明](analytic_curved_surface_usage.md)。

analytic 的针孔半宽和导出网格步长分别使用 `camera.pinhole_half_width_mm` 和 `render.mesh_step_mm`；下文 Zemax 表格中的同名参数仍用于 Zemax。旧 analytic 配置的同文件 `zemax` 段仅作兼容读取。

本项目模拟球冠压痕表面在彩色 LED 灯带照明下，经已标定针孔相机形成的 RGB 图像，提供两种后端：

- `analytic`：无需 Zemax 的确定性直接照明计算，适合快速调参和交叉验证。
- `zemax`：通过 Python.NET 调用 ZOS-API，自动建立非序列场景、设置漫反射、追迹三个光谱通道并输出相机图像。

仓库内的既有验证记录使用 Ansys Zemax OpticStudio 2024 R1、Premium 非序列模式。这里的图像是单视角 RGB 辐照度图；几何输入描述给定球冠形变，不求解接触力、弹性模量或胶体力学。

关于球冠几何、解析法线、相机投影和射线求交的数学推导，见[解析重建原理](解析重建原理.md)。

## 1. 环境与快速运行

以下命令均在**仓库根目录**执行，即包含 `pyproject.toml`、`simulate.py` 和 `configs/` 的目录；不要在 `docs` 目录执行。标定与 LUT 检验的完整新入口见 [仓库工作流](repository_workflow.md)。

### 1.1 同步 uv 环境

请先安装 uv，然后在仓库根目录的 PowerShell 执行：

```powershell
uv sync --locked
```

uv 根据 `uv.lock` 创建并同步项目内的 `.venv`，无需手动激活环境。`.python-version` 默认选择 Python 3.13，与既有验证环境一致。

Zemax 后端需要 Windows、64 位 Python、已安装的 OpticStudio 和可用的 ZOS-API 许可证。若本机缺少 Python 3.13，可先执行：

```powershell
uv python install 3.13
uv sync --locked
```

依赖统一声明在 [pyproject.toml](../pyproject.toml)，精确版本记录在 [uv.lock](../uv.lock)，两者应一起提交。

- 新增依赖：`uv add 包名`。
- 移除依赖：`uv remove 包名`。
- 更新依赖版本：执行 `uv lock --upgrade`，然后执行 `uv sync --locked`。

### 1.2 解析渲染

快速计算直接照明，并输出未压入参考帧：

```powershell
uv run python simulate.py --config configs/analytic.json --backend analytic --out results_analytic --reference
```

`--reference` 会使用相同曝光额外计算压入深度为零的参考状态，分别保存至 `indented/` 和 `reference/`。

### 1.3 Zemax 渲染

建立非序列场景并进行光线追迹：

```powershell
uv run python simulate.py --config configs/zemax.json --backend zemax --out results_zemax
```

只建立场景和归档，不追迹：

```powershell
uv run python simulate.py --config configs/zemax.json --backend zemax --build-only --out scene_only
```

`--build-only` 仅适用于 `zemax` 后端；`simulate.py` 必须显式指定 `--backend`。省略 `--out` 时，平面渲染写入仓库下的 `results_render/<backend>/<唯一运行标识>/`，曲面入口按生效曲率选择 `results_curve_render/analytic/<唯一运行标识>/` 或平面目录。显式 `--out` 优先，指定目录必须不存在或为空，历史结果保留原路径。

### 1.4 运行检查

检查几何、相机与辐射计算：

```powershell
uv run python -m unittest -v test_physics.py
```

## 2. 坐标与球冠

所有几何长度使用 mm。未变形接触面为以原点为中心、位于 $z=0$ 的有限矩形。

- 默认相机和灯带位于 $z<0$，光学反射面朝向 $-z$，即 `view_side_z=-1`。
- 平面默认 `direction_normal=-1`，压痕中心位移为 $z=-d$，朝向相机；旧配置字段 `direction_z` 仍兼容读取。
- 平面可以将 `view_side_z` 改为 `+1`，并相应移动相机和灯带；形变方向由 `direction_normal` 独立控制。曲面首版要求 `view_side_z=-1`、`direction_normal=-1`。

令 $R$ 为球半径、$d$ 为压入深度、$s$ 为形变方向符号，压入中心为 $(x_c,y_c)$。接触半径为：

$$
a=\sqrt{2Rd-d^2}.
$$

要求 $0\le d<R$，且接触圆严格位于矩形内部。令 $r^2=(x-x_c)^2+(y-y_c)^2$，则球冠内的高度为：

$$
z=s\left(d-R+\sqrt{R^2-r^2}\right),\qquad r<a.
$$

接触圆外高度为零。该模型在边界处位置连续，但通常斜率不连续，因而可能出现清晰的圆周边缘。模型不包含真实弹性膜在接触区外的平滑形变。小球只规定表面形状，不作为额外光学遮挡物加入场景。

## 3. 输入参数

参数由 [解析配置](../configs/analytic.json) 提供。下述示例值对应当前配置；它们不代表对实物参数的完整标定。

### 3.1 `surface`：接触面

| 参数 | 含义 |
| --- | --- |
| `size_mm` | 接触面 `[宽, 高]`，当前示例为 `[55.9, 21.8]` |
| `reflectance_rgb` | 三个独立光谱通道的漫反射率，范围 `[0,1]`，当前示例均为 `0.8` |
| `view_side_z` | 光学面朝向，取 `+1` 或 `-1` |

### 3.2 `indentation`：球冠压痕

| 参数 | 含义 |
| --- | --- |
| `center_uv` | 归一化基准曲面坐标，范围 `[-1,1]²`；当前示例约 `[0.0536673,-0.0733945]`，保持原 `[1.5,-0.8] mm` 的物理位置 |
| `radius_mm` | 小球半径，当前示例为 `6` |
| `depth_mm` | 压入深度，当前示例为 `1`；设为 `0` 得到未压入表面 |
| `direction_normal` | 沿基准几何法向的方向符号，当前示例为 `-1`；平面时与旧 `direction_z` 等价 |

### 3.3 `lights`：有限面积灯带

每个元素表示一段竖直矩形灯带。发光平面始终垂直于未变形接触面 `z=0`，固定朝向矩形内侧，不再自动瞄准世界原点。省略 `emission_model` 时保持历史的连续均匀发光；analytic 也支持下述逐点 RGB 功率模式。

| 参数 | 含义 |
| --- | --- |
| `side` | `left/right` 对应世界坐标 `-x/+x`，`top/bottom` 对应 `-y/+y` |
| `offset_mm` | 接触面边缘到竖直发光平面的向外水平距离；例如 `0.1` 表示平面距对应边界 `0.1 mm`，宽度不会改变该距离 |
| `z_mm` | 发光带中心线的有符号 Z 坐标；例如 `-1` 表示中心线位于接触面下方 `1 mm`，保留原有负 Z 侧约定 |
| `length_mm` | 发光带沿对应接触面边缘的长度；左右灯沿 Y，上下灯沿 X |
| `width_mm` | 发光带沿世界 Z 轴的完整宽度；范围为 `z_mm ± width_mm/2`，不是厚度 |
| `power_rgb_w` | `[R,G,B]` 三个独立光谱通道的总辐射功率，单位 W |
| `cosine_exponent` | 出射辐射强度正比于 $\cos^p\theta$，支持 `1～100`；`p=1` 为 Lambert 发光 |
| `samples_length`、`samples_width` | 仅控制 analytic 后端的灯带面积积分采样密度 |
| `along_offset_mm` | 可选，沿接触面边缘方向移动灯带中心，默认为 `0` |
| `normal_world` | 兼容性可选字段，只允许与该侧固定朝内法向同向；倾斜、朝外或零向量会报错 |

`power_rgb_w` 是辐射功率，不是电功率或 `0～255` 颜色值。例如 `[0.10,0,0]` 表示红光 `0.10 W`，`[0.05,0.05,0]` 表示红绿各 `0.05 W`。

#### analytic 逐点 RGB 光源

`configs/analytic.json` 现在使用 `emission_model: "discrete_rgb_points_v1"`，灯带沿长度方向按 `point_spacing_mm: 6.25` 排列。每点的 `point_power_rgb_w[i] = [R,G,B]` 为该点三个通道的绝对辐射功率（W）；三通道比例决定颜色，三通道之和决定该点总功率。允许零功率点，不自动归一化或保持总功率。所有灯带不能同时全灭。

该模式以 `point_spacing_mm`、`point_power_rgb_w` **替代** `samples_length`、`power_rgb_w`；同时填写新旧字段会报错。点数为 `floor(length_mm / point_spacing_mm) + 1`，整列居中，点距严格为给定值，端部留白均分，不拉伸间距来填满灯带。

| 侧面 | 长度 | 点数 | 各点沿灯带中心的偏移（mm） |
| --- | --- | --- | --- |
| left / right | 20 mm | 4 | -9.375、-3.125、3.125、9.375（沿世界 Y 递增） |
| top / bottom | 56 mm | 9 | -25、-18.75、-12.5、-6.25、0、6.25、12.5、18.75、25（沿世界 X 递增） |

`point_power_rgb_w` 按上述顺序填写，必须恰有对应点数行，每行三个有限非负数。例如将某一行改成 `[0.02, 0.01, 0]`，只调整该点为红光 0.02 W、绿光 0.01 W。第一次改造的等功率基线保留原先每边各 0.15 W 的总功率和颜色；后续优化允许改变总功率，当前配置采用下述平滑梯度方案。

灯带中心、长度、宽度、offset、Z、朝向不变。`samples_width` 仍对原宽度作均匀积分，每个 LED 的功率在这些积分节点间均分；这些宽度节点不是额外 LED，6.25 mm 指沿灯带长度的 LED 间距。CPU、CUDA eager、CUDA graph 和编译渲染共用同一套点位和功率。修改灯光后须新建 `AnalyticGpuContext`，旧上下文拒绝使用新灯光，避免复用旧 CUDA 常量。

逐点模型目前只支持 analytic；Zemax 收到该模式会明确报错，历史均匀灯带的 Zemax 行为不变。几何版本仍为 `vertical_edge_strips_v1`；发光模型版本和逐点功率包含在完整配置及既有标定签名中，旧样本和参考图不能复用为新分布的结果。改变功率后使用新的输出目录重新扫描和标定，标定、验证与 LUT quality 计算逻辑保持不变：

```powershell
.\.venv\Scripts\python.exe calibrate_lut.py --backend analytic --calibration-config configs/calibration.json --out results_lut/analytic/<new_run> --dry-run
.\.venv\Scripts\python.exe calibrate_lut.py --backend analytic --calibration-config configs/calibration.json --out results_lut/analytic/<new_run>
.\.venv\Scripts\python.exe -m experiment.lut_quality --lut-results results_lut/analytic/<new_run>
```

#### 最终采用方案：颜色梯度、端部加亮、下边减半

2026-10-23 用户要求停止搜索后，已终止在运行的候选，保留中断记录。当前 `configs/analytic.json` 采用完整完成的最佳方案 `bottom_half`，与[该运行的配置及签名](../results_lut/analytic/discrete_625_complement3_20261023/evaluation/light_distribution_spectral/bottom_half/manifest.json)完全一致。目标 `A(0.1)≤0.3024` 未达到，不标为优化目标完成。

26 个可独立控制的 RGB 发光点保持 6.25 mm 间距。左边 0.4 W 纯蓝、右边 0.4 W 纯绿，4 个点均分各边功率；上边 0.4 W、下边 0.2 W，各有 9 个点，总功率 1.4 W。长边点位为 `x=-25,-18.75,…,25 mm`，令 `t=x/28`、`g=(1+t)/2`，点功率权重为 `w=1+2t²`。各点总功率为 `P_side*w/sum(w)`；上边 RGB 比例为 `[0.75,0.25g,0.25(1-g)]`，下边为 `[0,g,1-g]`。宽度积分、灯带几何、相机、曝光和标定均保持原条件。

四侧固定发光法向分别为：left `[1,0,0]`、right `[-1,0,0]`、top `[0,1,0]`、bottom `[0,-1,0]`。修改 `offset_mm`、`z_mm`、`along_offset_mm`、尺寸或表面大小，只移动/缩放发光矩形，不旋转发光面。例如 `z_mm=-1, width_mm=2` 对应完整发光带高度 `[-2,0] mm`；均匀模式使用带内积分采样点，不包含矩形边缘。逐点模式按上表明确安排发光点，宽度方向仍使用带内积分节点。

### 3.4 `camera`：已标定针孔相机

| 参数 | 含义 |
| --- | --- |
| `width_px`、`height_px` | 输出分辨率，当前示例为 `640 × 480` |
| `fx_px`、`fy_px`、`cx_px`、`cy_px` | 已去畸变的针孔内参，单位 pixel |
| `position_mm` | 世界坐标相机光心，当前示例为 `[0,0,-60]` |
| `look_at_mm`、`up_world` | 观察目标和图像上方的世界方向 |
| `rotation_camera_to_world` | 可选的 `3 × 3` 正交旋转矩阵，存在时覆盖 `look_at_mm/up_world` |
| `focal_length_mm` | 针孔到像面的距离，当前示例为 `3`；像元尺寸由 $f/f_x$、$f/f_y$ 推出 |
| `response_rgb_3x3` | 三个入射光谱通道到相机 RGB 的线性响应矩阵，当前示例为单位矩阵 |
| `distortion_opencv` | 可选，目前仅允许全零，非零畸变会明确报错 |

像素中心坐标为 $u=0,\ldots,W-1$、$v=0,\ldots,H-1$，因此居中主点为 $((W-1)/2,(H-1)/2)$。实际标定主点可以偏离中心，且允许 $f_x\ne f_y$。

相机旋转矩阵的三列依次为右、下、前方向，采用 OpenCV 相机坐标约定。若已有外参：

$$
\mathbf X_c=\mathbf R_{cw}\mathbf X_w+\mathbf t,
$$

则光心位置为 $-\mathbf R_{cw}^{\mathsf T}\mathbf t$，相机到世界的旋转矩阵为 $\mathbf R_{cw}^{\mathsf T}$；平移量需要先换算为 mm。

默认观察原点、图像上方为 `[0,-1,0]`，此时画面右侧为世界 `+x`、画面下方为世界 `+y`。内参矩阵足以确定透视几何，但绝对像面辐照度还依赖针孔孔径和针孔到像面的距离。输入内参应对应已去畸变的图像。

### 3.5 `render`：展示与遮挡

| 参数 | 含义 |
| --- | --- |
| `shadows` | analytic 是否计算接触面自身的几何遮挡；使用 Zemax 后端时必须为 `true` |
| `exposure_scale` | 固定的展示曝光比例，所有帧共用，不逐帧自动归一化 |
| `tone_map` | `reinhard` 或 `clip`，仅影响展示 PNG，不影响线性 `.npy` 数组 |

### 3.6 `zemax`：连接、几何与追迹参数

| 参数 | 含义 |
| --- | --- |
| `install_dir` | OpticStudio 安装目录；换机器时修改，或设为 `null` 交给 NetHelper 查找 |
| `nethelper_dll` | 可选，指定 `ZOSAPI_NetHelper.dll` 的完整路径 |
| `mesh_step_mm` | STL 网格间距，当前示例为 `0.20`；减小可降低曲面离散误差 |
| `pinhole_half_width_mm` | 方形针孔的半边长 $b$，当前示例为 `0.004`，孔面积为 $(2b)^2$ |
| `rays_per_strip` | 每段灯带、每个有功率的光谱分量的发射光线数，当前示例为 `8000000` |
| `random_seed` | 随机采样种子；不同机器或并行线程调度可能仍产生数值差别 |
| `wavelengths_rgb_um` | 三个简化光谱波长，当前示例为 `[0.630,0.530,0.460]` μm |

Zemax 通过 Python.NET 加载 ZOS-API，启动独立实例并新建非序列系统。它不会连接当前已打开的镜头系统，当前配置也不以已有 `.zos/.zmx` 场景作为输入。

analytic 使用小孔极限下的投影与通光面积近似；Zemax 模拟有限大小的实际针孔，会产生少量几何模糊。该孔径参数不等价于完整的真实镜头模型；目前不包含衍射。

`rays_per_strip` 增大通常降低 Monte Carlo 噪声，同时增加计算量。具有多个非零光谱分量的灯带会建立多个光源分量，例如黄色灯带具有独立的 R、G 分量。

## 4. 两个后端的物理计算

### 4.1 analytic

根据每个像素对应的针孔视线，与有限平面和球冠求最近交点，并求解析法线。对有限面积灯带计算直接照明，考虑发光角分布、距离平方衰减、入射余弦和自遮挡。表面采用 Lambert BRDF $\rho/\pi$，再由表面辐亮度得到理想像面辐照度：

$$
E_{\mathrm{sensor}}=L\frac{A_{\mathrm{hole}}}{f^2}\cos^4\theta.
$$

该模型只计算直接照明，没有间接反弹。它采用确定性积分，适合当前理想模型下的批量数据生成。

### 4.2 zemax

表面使用开曲面 STL、`MIRROR` 材质、按波长设置反射率的 `TABLE` 镀膜，以及全比例 Lambert 散射。灯带使用有宽度和朝向的 Source Rectangle；相机由四个吸收矩形围成方形针孔，针孔后方放置 Detector Rectangle。

散射使用面向针孔的重要性采样，并保留能量权重。RGB 分别追迹并读取像面辐照度；三个独立光谱通道经用户的相机响应矩阵形成展示 RGB，不以 Zemax 的 CIE 显示色代替相机响应。

探测单位显式设置为 `W/mm²`，之后转为 `W/m²`。停用某个源分量时使用可忽略的正功率，因为 OpticStudio 会将恰好为零的源功率重置为默认 `1 W`。光线误差能量记录到 `metadata.json`；超过源能量的 $10^{-6}$ 时会报错。

散射方向集中于针孔，当前场景用于直接照明成像，不保证重现复杂场景的多次间接反弹。

## 5. 输出文件

| 文件 | 含义 |
| --- | --- |
| `image.png` | 固定曝光、相机响应矩阵、色调映射和 sRGB 编码后的预览 |
| `sensor_irradiance_rgb_w_m2.npy` | `H × W × 3` 浮点线性像面辐照度，单位 `W/m²`，位于相机响应矩阵和展示曝光之前 |
| `radiance_rgb_w_m2_sr.npy` | 仅 analytic 输出，表面交点的辐亮度，单位 `W/(m²·sr)` |
| `geometry_gt.npz` | `mask`、`position_mm`、`normal_world`、`depth_mm`；无有效交点时 `mask=false`，其余几何量为 `NaN` |
| `metadata.json` | 完整输入、后端、辐射单位；完整 Zemax 追迹还记录各通道耗时和能量诊断 |
| `surface.stl` / `tactile_*.STL` | 光学曲面的三角网格，单位 mm |
| `tactile_*.DAT` | Zemax 使用的独立镀膜表，定义各波长的反射率 |
| `scene_R.zos`、`scene_G.zos`、`scene_B.zos` | 分别追迹 R、G、B 时保存的场景 |
| `scene.zos` | 恢复全部有效 RGB 光源的完整场景 |
| `scene.zar` | 包含主场景所需 STL、镀膜等依赖的归档，建议使用 Restore Archive 打开 |
| `scene*.ZDA` | OpticStudio 会话文件，保存窗口、分析设置及已计算数据，可能包含探测器结果 |
| `scene.PAF` | OpticStudio 路径分析数据，用于检查光线路径和通量 |
| `unmasked_sensor_irradiance_rgb_w_m2.npy` | Zemax 应用接触面视野遮罩之前的诊断数组 |

`depth_mm` 是相机坐标的前向 Z 深度，不是射线长度或压入深度。Zemax 输出的几何真值来自解析球冠，实际追迹使用其 STL 近似。

正式 `image.png` 和像面辐照度数组把接触面以外的像素置黑。展示曝光、色调映射和颜色响应不会修改保存的线性光谱数组。

`scene.zos` 中的光源最终恢复为全部有效 RGB 分量，但附带的探测器数据仍是最后一次 B 通道追迹的结果。要重现脚本合成 RGB，应重新运行程序分别追迹三个通道。当前不保存完整 `.ZRD` 光线数据库。

使用 `--build-only` 时只输出场景、几何、镀膜、归档和构建元数据；不生成图像或追迹辐照度。

### 5.1 Zemax 数据目录中的依赖

运行 Zemax 时，会在当前 Zemax 数据目录的 `Objects/CAD Files` 和 `Coatings` 下新增带唯一前缀的 STL、镀膜文件。不会修改已有 `COATING.DAT`、已有打开的镜头系统或全局文件夹配置。

这是当前 OpticStudio 2024 R1 场景导入 STL、镀膜所需的处理。完整追迹输出的 `metadata.json` 记录新增文件的位置。依赖普通 `.zos` 文件时应保留这些依赖；跨机器分享模型优先使用 `scene.zar`。图像、NumPy 数组和几何真值应另行保留。

## 6. 模型边界

当前模型包括表面自身遮挡、彩色有限面积灯带和相机透视，省略透明胶体折射、体散射、真实镜头像差、畸变、景深、衍射、电子噪声及胶体力学。

仅有尺寸、相机内参和位姿，无法唯一确定实物图像的亮度和颜色。还需要灯带辐射功率与发光角分布、表面反射率、相机光谱响应或实测颜色标定，以及曝光参数。

替换为真实相机光学模型时，可保留表面几何与灯带描述，将针孔相机替换为非序列镜头模型；若仅已知内参与畸变参数，应使用与标定相匹配的相机投影模型。
