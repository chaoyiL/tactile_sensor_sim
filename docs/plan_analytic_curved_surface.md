# analytic 等曲率弯曲与归一化曲面坐标实施计划

日期：2026-10-23。状态：已按本方案实施 analytic 曲面、统一位置输入、CPU/CUDA 渲染、编译与执行图；正文保留原设计依据。实际接口见[使用说明](analytic_curved_surface_usage.md)，已执行的验证及边界见[验证记录](analytic_curved_surface_validation.md)。

目标是增加独立入口 `simulate_curve.py`，用 analytic 渲染沿 X 方向等曲率弯曲的传感器表面，并支持沿局部法向的球压入。平面和曲面的压入位置统一为归一化曲面坐标。弯曲参数放在 `configs/analytic.json`，不新增第二份可编辑仿真配置。

## 1 已确认的需求与范围

用户已确认以下几何约定：

| 项目 | 约定 |
|---|---|
| 弯曲方向 | 沿 X 弯曲，Y 保持直线，即圆柱面的一段圆弧 |
| 弯曲朝向 | 两侧朝世界坐标 −Z 弯曲，也就是向当前相机靠近 |
| 曲面中心 | 未压入曲面中心固定在世界原点，中心切平面仍为 Z=0 |
| 相机 | 正对曲面中心，弯曲前后与该中心的距离不变 |
| 灯带 | 随曲面边缘弯曲，发光面保持垂直于局部基准曲面、朝局部内侧 |
| 压入位置 | 使用 `[-1,1] × [-1,1]` 的归一化曲面坐标，中心为 `(0,0)` |
| 压入深度 | 从未压入曲面上的指定位置，沿该位置的局部法向推进 |

本阶段实现 analytic 的弯曲几何、照明、遮挡与输出。analytic 的 CPU 和普通 CUDA 路径均属于实现范围；编译内核和 CUDA Graph 分阶段接入，不能复用含平面假设的旧内核来渲染曲面。

平面位置输入的统一覆盖现有仿真入口及标定姿态接口。Zemax、Xense 只做平面坐标输入的适配，不实现它们的弯曲版本。曲面 LUT 标定、曲面 NormDiff 和曲面 LUT 检验不在本阶段范围，现有标定入口遇到非零曲率应明确拒绝。

## 3 统一曲面坐标和基准几何

### 3.1 坐标含义

记 `surface.size_mm=[W,H]`。W、H 表示未压入表面的展开长度，弯曲不改变它们。W 是 X 方向的完整弧长，H 是未弯曲 Y 方向的长度；W 不是弯曲后的弦长或图像投影宽度。

定义归一化坐标 `(u,v)` 和展开坐标 `(s,t)`：

```text
u, v ∈ [-1, 1]
s = u W / 2    [mm]
t = v H / 2    [mm]
```

`u=-1/+1` 分别对应左/右边，`v=-1/+1` 分别对应现有 top/bottom，即世界 −Y/+Y。它们不是图像像素坐标。

坐标以**已经弯曲但尚未局部压入的基准曲面**为参照。压入后仍使用这套标签，不随凹坑产生的额外弧长重新归一化。后续用沿基准法向的映射给接触区赋坐标；这是一种规定的运动学对应，不宣称求解了真实材料的切向流动或弹性应变。

### 3.2 圆弧参数化

曲率半径记作 R，探测球半径另记作 r，避免混淆。R 为有限正数，定义：

```text
α = s / R
B(s,t) = (R sin α, t, R(cos α − 1))
T_s    = (cos α, 0, −sin α)
T_t    = (0, 1, 0)
N      = (sin α, 0, cos α) = T_s × T_t
```

其中 B 是基准曲面，`T_s`、`T_t` 是单位切向，N 是中心朝 +Z 的几何法向。两方向的一阶长度均保持不变；X 方向曲率为 `1/R`，Y 方向曲率为 0。

基准光学法向为 `surface.view_side_z * N`。本次曲面使用当前的 `view_side_z=-1`；不要把朝相机的光学法向和几何正向混成一个字段。

中心与两侧满足：

| 曲面坐标 | 世界位置 |
|---|---|
| `(0,0)` | `(0,0,0)` |
| `(-1,0)` | `(-R sin(W/2R), 0, R(cos(W/2R)−1))` |
| `(+1,0)` | `(+R sin(W/2R), 0, R(cos(W/2R)−1))` |

以 `W=55.9 mm, R=100 mm` 为例，边缘转角约 `16.0142°`，两侧位于 `X=±27.5875 mm, Z=-3.88065 mm`。这里只是示例曲率，不作为用户指定的唯一曲率。

第一版支持 `W/(2R) < π/2` 的开放圆弧，避免超过 180° 的回绕。当前宽度对应 `R > 17.7935 mm`；这只是角度条件，仍须满足压入、光源和相机的合法性检查。对更紧的弯曲明确报错，不自动增大 R。

平面使用 `radius_mm=null`，数学上对应曲率为零：`B=(s,t,0)`。不使用 JSON 的 Infinity，也不以一个很大的有限 R 偷换平面。有限大 R 的计算使用稳定形式，例如 `Z=-2R sin²(α/2)`，避免 `cos(α)-1` 的消减误差。

### 3.3 原坐标到新坐标

平面上 `s=x, t=y`，因此：

```text
u = 2x / W       x = uW / 2
v = 2y / H       y = vH / 2
```

当前 `[1.5,-0.8] mm` 精确转换为约 `[0.053667262969588556,-0.07339449541284404]`。新公共字段定为 `indentation.center_uv`。弯曲后，同一 `(u,v)` 保持同一展开位置，世界坐标由 B 得到，不能继续把 `[s,t]` 当作世界 `[X,Y]`。

## 4 球压入采用真实球面与局部法向

### 4.1 球的位置与推进方向

给定压入位置 `(u₀,v₀)`，先得到基准点 `B₀=B(s₀,t₀)` 及法向 `N₀`。令 `ε=indentation.direction_normal`，压入方向为 `D₀=εN₀`，球心为：

```text
C(d) = B₀ + (d − r) D₀
```

当前常规压入取 `ε=-1`，即从 +N 一侧向 −N 推进。球从 `C(0)=B₀−rD₀` 的相切位置移动 d mm，中心压入点为 `B₀+dD₀`。球半径不变，球在世界坐标中保持球形。

`center_uv` 是基准接触锚点，不是球心的投影。它在弯曲曲面上指定球的初始相切位置。d 是该位置法向上的推进距离，不是世界 Z 高度差，也不是相机深度。

平面配置中 `direction_normal` 与旧 `direction_z` 的数值等价。平面保留旧的 ±1 能力；曲面首版要求 `direction_normal=-1`，反向形变须另行扩展和验证，不能用 `direction_z` 冒充局部法向。

### 4.2 接触区与表面拼接

沿用现有模型的范围：接触区贴合刚性球面，接触区外保持基准形状，不求解膜张力、弹性松弛或接触区外的平滑过渡。接触边界位置连续，法向可能有折角。探测球只规定表面形状，不作为额外的完整光学遮挡球。

采用以下可检验的局部法向图定义，而不把平面球冠绕成一个已不再是球面的凹坑：

```text
对基准点 B=B(s,t)，D=εN(s,t)，令
a = (C−B)·D
b = |B−C|²−r²
δ = a + sqrt(a²−b)
P(s,t) = B(s,t) + δD
```

接触域取基准曲面落在球内的区域 `|B−C|² < r²`，并要求它是包含锚点的单个局部连通区域。域外令 `δ=0`；域内取沿 D 离开球体的根，得到真实球面上的 P。必须验证整个接触域及边界满足局部分支条件，特别是边界上 `a<0`，使 `δ→0`；不能仅用 `max(δ,0)` 掩盖非局部穿透、分支切换或不连续。

曲面首版的 `ε=-1` 还要求 `δ<R`，法向坐标不能穿过圆柱轴；所有姿态都必须保持有效的单值对应。若球太大、压入太深或曲率太紧导致条件失败，返回带参数和路径的错误，不能改为近似球冠。

接触区的几何正向法向为 `ε(P−C)/r`，并检验它与基准 N 同侧；光学法向再乘 `view_side_z`。域外使用 N。交界点使用固定的边界归属规则，交点所属部件与输出法向保持一致。

接触边界由圆柱与球面的交线确定，一般不是展开平面或世界 XY 中的圆。因此旧公式 `sqrt(2rd−d²)` 只保留给平面路径，不能用来裁剪曲面接触区、判断越界或生成曲面扫描边界。

第一版要求完整接触区严格位于曲面矩形内部。通过球到四条基准边界的最小距离、接触区拓扑及分支检查验证；不能仅采样几个边界点就宣称没有越界。深度为零时直接返回无压入基准曲面。

## 5 随曲面运动的灯带

弯曲仅改变灯带的安装几何。当前 `uniform_strip_v1`、`discrete_rgb_points_v1` 的发光模型、RGB 功率、余弦指数及采样数量继续保留。

### 5.1 局部安装规则

在曲面边缘的基准点 B 处，令 M 是曲面切平面内的向外单位方向：

| 灯带 | 边界 | M | 发光法向 |
|---|---|---|---|
| left | `s=-W/2` | `−T_s` | `+T_s` |
| right | `s=+W/2` | `+T_s` | `−T_s` |
| top | `t=-H/2` | `−T_t` | `+T_t` |
| bottom | `t=+H/2` | `+T_t` | `−T_t` |

发光带上的点满足局部安装关系：

```text
L = B + offset_mm M + z N
z ∈ [z_mm − width_mm/2, z_mm + width_mm/2]
```

因此 `offset_mm` 是沿边缘局部外向切线，从边缘到发光带的间隙；`z_mm` 是相对基准曲面、沿 N 的有符号安装高度；`width_mm` 是沿 N 的完整带宽。这是平面定义的明确曲面扩展，平面极限恢复原来的世界 XY 间隙和世界 Z 高度。

left/right 灯带仍是沿 Y 的直条，其整体位置和朝向随所在边缘转动。top/bottom 沿 X 成为弧形带。对本次圆柱几何，top/bottom 的发光法向仍为固定 ±Y，但带宽方向 N 随弧长变化。所有灯带都不自动瞄准世界原点，也不跟随局部球压入变形。

### 5.2 长度与功率守恒

`length_mm` 和 `point_spacing_mm` 继续表示**灯带中心线自身的实际弧长**，不能因为挂到不同半径上就悄悄改变 LED 间距或灯带长度。

对 top/bottom，设 `z₀=z_mm`，中心线半径为 `R+z₀`。沿灯带中心线的有符号距离为 ℓ，`along_offset_mm` 表示沿基准边缘的中心定位弧长，则：

```text
s_center = along_offset_mm
s(ℓ) = s_center + ℓ R/(R+z₀)
```

在这个 s 上按上一节的安装公式计算每个宽度采样点。left/right 则使用 `t=along_offset_mm+ℓ`。对超出有限曲面角点的灯带端部，沿同一圆柱支架延伸，不截断 LED、不改变功率；校验延伸后的角度及光源与表面关系。当前 top/bottom 长度 56 mm 略大于表面展开宽度 55.9 mm，必须覆盖这一实际情况。

连续灯带按实际发光面积分配采样权重，并归一化到原 `power_rgb_w`。top/bottom 带宽处的面积因子为 `(R+z)/(R+z₀)`；不能一面改变采样面积，一面把均匀面功率误写成均匀参数功率。离散 LED 保持每点 `point_power_rgb_w[i]` 不变，宽度样本只分摊该 LED 的功率，不增加 LED 数量。

校验整个带宽满足 `R+z>0`。记录实际样本位置、朝向、每点功率及每通道总功率。光源接口统一返回逐采样点法向，便于 CPU、CUDA 和输出使用同一几何定义。

## 6 相机与 analytic 渲染

### 6.1 相机约束

本次曲面保持中心 `B(0,0)=(0,0,0)`，相机位于 `(0,0,-D_cam)` 并朝向中心。沿用原配置的 D_cam、相机内参、像素分辨率、up 方向、响应矩阵、曝光和色调映射；当前 D_cam 为 60 mm。

对不满足居中、正对条件的曲面配置明确报错，提示调整配置，不静默重设用户相机。正常弯曲不移动相机；球压入时也不让相机跟随局部凹坑。这里固定的距离是到**未压入基准曲面中心**的距离。

保留透视投影。曲面边缘的投影位置、可见面积及距离变化是渲染结果的一部分，不拉伸图像去填满原来的矩形。检查变形表面未到达相机或穿过相机平面，并输出真实有效像素掩膜。

### 6.2 解析求交与遮挡

未压入基准面满足圆柱方程：

```text
X² + (Z+R)² = R²
```

相机射线和阴影射线使用同一个几何求交接口：

1. 解射线与圆柱的交点，恢复 `α=atan2(X,Z+R)`、`s=Rα`、`t=Y`，按弧长边界裁剪，并排除已经被球面替换的接触域。
2. 解射线与球的交点。通过圆柱轴向投影恢复基准坐标，再检查第 4 节的接触域、δ、有效分支和有限表面边界，剔除完整球上不属于传感器表面的点。
3. 从有效候选中取最近正向交点，返回距离、部件标识、位置、曲面坐标及几何/光学法向。

当 `ρ=sqrt(X²+(Z+R)²)>0` 时，球面点的基准投影可写为：

```text
B = (R X/ρ, Y, R(Z+R)/ρ − R)
δ = ε(ρ−R)
```

需要显式处理轴向平行射线、切线、无交点、很大 R 的数值稳定性，以及接触边界的浮点容差。求交可用相对局部圆心的表达，但不能用两个巨大近似值相减形成数值不稳定的半径差。空交点不得产生可参与照明的 NaN 坐标。

阴影对实际弯曲和压入后的表面求交，包含曲面自身的遮挡。仅在光源之前的交点造成遮挡；法向偏移与相交容差按几何尺度统一管理。不能只更新相机几何、仍用平面判断阴影。

照明继续使用现有距离平方衰减、入射余弦、发光余弦、Lambert 反射及针孔传感器换算。保持 W、mm、W/m² 和 W/(m²·sr) 的单位换算，以及线性辐射数据与显示 RGB 的区分。

### 6.3 实现边界与加速

建议增加 `utils/surface_coordinates.py` 管理坐标解析和公共参数，增加 `utils/curve_geometry.py` 管理圆柱、局部球面及灯带安装，另提供对应的 Torch 实现。公共接口包含类型标注，CPU 与 CUDA 使用相同的语义、分支、边界规则和姿态参数。

在现有 analytic 渲染分发中按 `geometry_model_id` 选择几何实现，复用照明、响应、显示编码及保存逻辑。保留经过验证的平面路径，禁止通过新全局常量把所有历史结果改称曲面模型。

先交付 CPU 参考及普通 CUDA，再对曲面阴影内核接入编译和 CUDA Graph。加速尚未支持时，`compile_lighting=required` 明确报错；`auto` 可走普通 CUDA，但必须记录原因和实际执行模式。`cuda_graphs=true` 暂不可用时也应报告。不能默默退到 CPU，更不能降低分辨率、光源样本量或几何精度。

缓存键和上下文兼容检查加入曲率、曲面尺寸、弯曲方向、坐标版本、相机、灯带安装及发光参数。仅球位置和深度可作为受控的姿态更新；改变曲率或灯带时重建几何和光照常量，并使参考帧缓存失效。

```json
  "render": {
    "mesh_step_mm": 0.2
  }
}
```

这是合并到现有配置的片段，不是一份可替代全部配置的完整 JSON。初次迁移将曲率半径默认设为 null，保留现有平面运行条件；弯曲时显式填写正数，或用 CLI 覆盖。

`axis` 首版只接受 `x`，弯曲 `direction_z` 只接受 −1。灯带随曲面安装是这一几何模型的固定语义，元数据记录 `edge_attached_local_frame_v1`，暂不增加尚未实现的固定灯带选项。

旧 `indentation.direction_z` 与新的 `surface.bending.direction_z` 含义不同，错误提示和文档必须带完整字段路径。`camera.pinhole_half_width_mm`、`render.mesh_step_mm` 分别接替 analytic 原本对同文件 `zemax` 段的读取。旧位置字段在正常新配置中移除，只保留兼容读取，不能有两个可编辑真值来源。

### 7.2 入口行为

`simulate_curve.py` 为薄入口，流程在可复用模块中实现。固定使用 analytic，默认读取 `configs/analytic.json`；如果配置声明别的后端，直接拒绝。提供：

| 参数 | 行为 |
|---|---|
| `--config` | 指定 analytic 配置路径 |
| `--out` | 独立结果目录；默认按生效曲率选择 `results_render/analytic/<唯一运行标识>/` 或 `results_curve_render/analytic/<唯一运行标识>/`；非空目录拒绝覆盖 |
| `--radius-mm` | 覆盖弯曲半径，有限正数；只在新入口提供 |
| `--flat` | 显式设置曲率为零，用于同一流程的平面对照；与 `--radius-mm` 互斥 |
| `--center-uv U V` | 覆盖归一化压入位置 |
| `--depth-mm` | 覆盖沿局部法向的深度 |
| `--device` | `cpu` 或 CUDA 设备，与现有 analytic 行为一致 |
| `--reference` | 同曲率、同灯带、同相机和曝光的零深度参考帧 |
| `--dry-run` | 校验并展示生效参数、锚点/球心、边缘转角和下沉量、光源及像素数、输出位置；不渲染、不写入、不初始化 GPU |

覆盖优先级为 CLI > JSON > 明确默认值；未提供 CLI 值不得覆盖 JSON。`--flat` 与 `--reference` 是独立概念：前者取消全局弯曲，后者只取消局部压入。

保留 `simulate.py` 的平面用途，并让它接受统一的 `center_uv`。它遇到非零 `surface.bending.radius_mm` 应提示使用 `simulate_curve.py`，不能忽略曲率继续输出平面。`calibrate_lut.py`、Zemax 和 Xense 遇到非零曲率同样明确报不支持。

实现后的预期命令：

```powershell
# 查看接口及参数，不创建输出
.\.venv\Scripts\python.exe simulate_curve.py --help
.\.venv\Scripts\python.exe simulate_curve.py --config configs/analytic.json --radius-mm 100 --dry-run

# 曲面及同曲率的零压入参考
.\.venv\Scripts\python.exe simulate_curve.py --config configs/analytic.json --radius-mm 100 --center-uv 0.3 -0.2 --depth-mm 1 --reference --out results_curve_render/analytic/curve_r100_run01

# 通过相同坐标和照明语义生成平面对照
.\.venv\Scripts\python.exe simulate_curve.py --config configs/analytic.json --flat --reference --out results_render/analytic/flat_run01
```

## 8 平面接口迁移与历史兼容

坐标统一在配置/姿态边界集中处理，不能在三个后端各自复制换算公式。

1. 新配置只写 `center_uv`，默认迁移 `configs/analytic.json`、`configs/zemax.json`、`configs/xense.json` 的平面位置。各自按自己的 `surface.size_mm` 转换，保留原来的物理位置。
2. 旧 `center_xy_mm` 只在平面或历史平面快照的兼容读取中转换。新旧位置字段同时存在时拒绝，避免来源冲突。非零曲率搭配旧 XY 字段时拒绝，要求用户明确采用曲面坐标。
3. 旧方向字段仅在平面中转换为 `direction_normal`。对新旧方向或新旧相机通量参数同时存在的冲突值报错；迁移信息记录在输出元数据中。
4. 给 Zemax/Xense 的现有平面渲染适配器输出派生 XY mm；Xense worker 可以继续使用原有毫米协议。这不改变它们的物理模型，也不表示它们支持弯曲。
5. `ScanPose` 的公共位置逐步改为 `center_uv`，并记录展开毫米位置；`center_xy_mm` 可暂留为明确仅对平面有效的派生兼容接口。原 `scan.xy_step_mm` 继续表示平面物理采样步长，本阶段不重命名或改变采样密度。先按原算法生成相同毫米姿态，再无损换算标签，避免浮点往返改变端点判断。
6. 核对 `calibration_samples`、GPU 姿态更新、Zemax/Xense 适配器、可视化、清单与续跑比较等所有读取 `center_xy_mm` 的位置。位置标签变化不允许改变扫描姿态、留出划分、接触边界或 LUT 法向定义。
7. 不批量改写 `configs/legacy/`、已有运行的配置快照、manifest、样本、LUT 或失败状态。旧格式走版本化读取；新结果记录坐标 schema。格式变化引起的续跑兼容性需要显式验证，不能仅因物理值看起来相近就自动复用。

本阶段只把平面标定接口接入新位置约定。新增曲面几何不会自动进入 LUT 采样、法向标签、NormDiff 或既有评估；这些路径应识别并拒绝不支持的曲面模型。

## 9 输出与可复现性

继续保存 `image.png`、`sensor_irradiance_rgb_w_m2.npy`、`radiance_rgb_w_m2_sr.npy`、`geometry_gt.npz` 和 `metadata.json`。支持保存弯曲后 STL 供查看，网格仅用于导出和诊断，analytic 图像不依赖 STL 网格近似。

| `normal_geometric_world` | 最终表面的几何正向法向，中心朝 +Z 的约定 |

无效像素的几何值统一为 NaN，掩膜为 false。元数据至少记录：

- 原始配置与实际生效配置、CLI 覆盖、坐标范围和单位、输入位置与展开位置、锚点、世界球心及推进方向。

- 参考帧是否同曲率、运行状态，以及数值容差和任何显式加速回退。

建议模型名为 `cylinder_x_sphere_contact_v1`、`surface_uv_signed_v1` 和 `edge_attached_local_frame_v1`。它们进入参考图、几何和 GPU 缓存的兼容判断。平面历史模型继续使用原标记，不统一改名。

输出必须使用新目录；失败目录保留诊断，不当作已完成结果覆盖。按用户后续指定的目录规则，无弯曲渲染默认放在 `results_render/<backend>/<唯一运行标识>/`，有弯曲渲染放在 `results_curve_render/analytic/<唯一运行标识>/`；零压入参考保持当前曲率，归入同次运行。显式 `--out` 优先，历史 `results/`、`results_curve/` 不搬移。该功能不发布 LUT，不写入 `results_lut/`。

## 11 验收与验证计划

测试使用独立 fixture，不依赖用户持续调整的 `configs/analytic.json`。数值参考包含直接公式、已知交点及既有平面实现；不把同一生产函数的输出复制成期望值，不改写 `tests/compile_reference/`。

### 11.1 配置与几何

- 坐标：中心、四角、随机内部点及旧示例双向转换；拒绝越界、NaN、错误长度、bool 冒充数值与新旧字段并存。
- 弯曲：中心不动、两边等高且 Z<0、弧长和曲率正确、切向正交、几何法向单位化；R 变大趋近平面，null 精确走平面。
- 压入：零深度；中心及左右偏心位置的球心运动为 dD₀；接触点满足球面方程；锚点位移恰为 d；域外无位移、边界连续。
- 接触限制：曲面边缘越界、非局部接触、分支不连续、接近轴线或退化的姿态必须拒绝。小 d、接触域接近边界及强曲率用独立构造覆盖。
- 求交：已知圆柱/球面交点、斜射线、两根取近、切线、轴向平行、无交点、接缝、光源前后的遮挡；大 R 样例检查消减误差。
- 灯带：局部间隙、完整带宽、长度、点间距和朝向；左右直条与上下弧带；连续/离散两模式的采样数及 RGB 总功率不变；有限表面以外的小段灯带不被裁掉。

### 11.2 图像与兼容

- 同一固定配置在平面模式下，对比修改前 CPU/CUDA 的位置、法向、mask、辐射和显示结果；位置输入改名不应改变物理结果。
- 同曲率参考帧只取消压入，保留相机、灯带和曝光。与平面参考的区别在文件和元数据中明确体现。
- 中心与偏心压入均验证透视投影往返、世界球心、曲面 UV 和接触区。对称性仅使用特制的对称相机与灯带 fixture，不假定当前 RGB 配置对称。
- 在相同分辨率、发光样本数、精度与阴影设置下比较 CPU、普通 CUDA；再比较编译/执行图。不得靠减少采样或屏蔽不一致像素过测。
- 平面回归保持既有测试容差。新曲面 float64 非退化固定样例建议位置绝对误差不超过 `1e-8 mm`，法向分量误差不超过 `1e-9`，CPU/CUDA 辐射相对误差不超过 `1e-8` 并附接近零值的绝对阈值。实施时先把绝对阈值写入固定 fixture 的验收定义，遇到失败分析原因，不能事后为了通过而放宽。
- 接缝与切线附近另设显式分类测试，检查位置连续性、固定部件归属和可见性容差；这类样例同样必须验收，不从结果中悄悄剔除。默认 float32 辐射路径单独记录与 float64 的误差，不能用 float64 通过代替实际默认路径验证。
- 平面标定的完整姿态序列、数量、物理步长、留出划分及原有法向标签保持一致；Zemax/Xense 仅验证坐标适配和拒绝曲率的行为。实际后端运行需要各自环境，不以适配单测声称完整后端验证通过。
- 改变 R、灯带或相机必须使相关缓存失效；改变球姿态必须更新球心及阴影参数。旧结果按原版本读取，不能复用到新曲面条件。
- `--help` 可在无 CUDA 环境运行；`--dry-run` 不渲染、不写文件、不启动 GPU/其他后端；非空输出目录报错。归档的有效配置能还原本次运行条件。
